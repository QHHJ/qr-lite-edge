# QR Lite：Edge 本地二维码识别

基于 https://github.com/monyxie/qr-lite ，上游提交 `b41ede564aa20d5372e0969396f42e20016af62f`。
继续使用原项目的 Manifest V3、OpenCV WASM、WeChat QRCode 模型和图片处理逻辑。

## 安装

1. 在 Edge 地址栏打开 `edge://extensions`。
2. 开启「开发人员模式」，点击「加载解压缩的扩展」。
3. 选择本项目的 `dist/edge` 文件夹（里面有 `manifest.json`）。
4. 将 QR Lite 固定到工具栏。

重新构建：安装 Node.js 和 pnpm，执行 `pnpm install`，再执行 `pnpm build:edge`。
保留原有 yarn 构建方式，也可以运行 `yarn build:edge`。

## 使用

- **网页图片**：右键图片 → 识别二维码，单击即识别，不展开子菜单。
- **框选区域**：网页空白处右键 → 识别二维码，或插件扫描页 → 选择区域扫描；按住左键拖出矩形，松开识别。原有滚轮调整方框、单击识别仍然可用。Esc 退出，R 重新扫描。
- **页面截图**：点击插件 → 识别当前页面截图。只截当前可见区域。
- **粘贴截图**：打开插件并使其获得焦点，按 Ctrl+V。
- **本地图片**：打开插件后选择图片，或把图片文件拖入插件窗口。
- **多个二维码**：图片上显示全部已识别二维码的编号框；点击框或下方对应结果选择。复制和打开链接作用于所选结果。多个二维码不会自动打开第一条链接。

识别完全在本地进行：WASM 和模型随插件打包，不上传图片、不调用外部识别 API。
右键取图可能重新读取原网页图片；用户点击「打开链接」后会正常访问目标网站。
沿用原项目本地历史记录设置，可在设置页关闭或清空历史。

浏览器内部页面、扩展商店等受保护页面不能注入框选工具；可先截图再粘贴识别。
跨域图片如果无法直接读取，则尝试识别图片当前可见部分的截图。检测到的所有结果都会保留，但模糊、遮挡或过小的码不保证识别。

本次改动未替换 decoder，也未加入服务器、账号或外部识别依赖。

## 原有调用链与改动范围

- 图片：`popup.js → Scanner → ImageScanner → qrcode.scan → OpenCvQrCodeDecoder.decode → WeChatQRCode.detectAndDecode`。
- 区域：`picker-loader.js` 注入扩展 iframe → `picker.js` 发送 `BG_CAPTURE_SCAN` → `background.js` → `capturePartialScreen` 裁剪截图 → 同一个 `scan`。
- 原右键图片路径：菜单传入 URL、tab/frame 信息 → 注入 `imageRetriever` → Canvas 读取原图；受跨域限制时返回截图裁剪参数。
- decoder 原本就返回 `{content, vertices}[]`；原界面只取首项。本次只扩展结果状态、原有 SVG 标记组件和结果选择控件。
- Ctrl+V、复制、打开链接沿用原有实现；补本地图片、拖入、可见页面截图和拖拽矩形入口。

## 验证

运行 `pnpm build:edge` 后执行 `pnpm test:edge`。默认使用 Windows 安装的 Edge，可用 `EDGE_PATH` 指定其他路径。

已在 Edge `153.0.4234.32` 中加载实际构建产物验证：

- 双码图片识别、全部坐标标记、点击框和结果按钮切换、复制所选内容。
- 文件选择，以及模拟剪贴板图片事件和文件拖放事件。
- 通过真实扩展按钮授权后截取网页、150% 像素比例下拖拽矩形截图识别。
- 同源网页的原有注入取图函数；原生右键菜单点击本身未做自动化验证。
- 图片识别页无外部 HTTP 请求、无页面脚本异常。
- ESLint 无源码问题，生产构建成功；保留原有模型体积警告。

测试截图与二维码样本在 `.local/edge-test`，不进入扩展包。

右键菜单只保留一个「识别二维码」入口：图片（包括带链接的图片）直接识别，其他网页区域进入框选。生成二维码和摄像头功能仍可从插件窗口进入。
